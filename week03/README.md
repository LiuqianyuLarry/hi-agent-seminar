# Week 3: tools, DeepSeek function calling and MCP

Condition monitoring gives the engineering purpose: use measurements, maintenance
history and equipment references to assess operation. CONV-3 is the common
classroom conveyor. Its records are outside the model, so our application must
provide controlled access. We build a tool-using assistant foundation, with at
most one tool per turn, not an autonomous fault-diagnosis system.

Choose between two genuinely different 100-minute paths:

| Path | What happens |
|---|---|
| Review lecture + code | Show the original PPT page, explain its diagram and example in plain English, then connect it to the actual lecture code and seminar exercise. |
| Start seminar practice | Enter the temperature-tool exercises directly, with the concepts and detailed code explanations needed for each task. |

Both paths use logic then code, optional foundation explanations, the same core
learning checks, and the full MCP introduction before its exercise. There is no
required mathematics segment. Each path has two 50-minute sessions; additional
scenario scans and boundary tests are optional.

Students complete three Python tools and one MCP wrapper. The mentor saves their
code from chat, supervises real tests, explains the observed outputs and checks
understanding. Questions focus on how tools are described, requested, validated,
executed and connected to the model. Optional basics may be skipped; required
practical verification may not.

The lecture demonstrates maintenance history; the seminar reads temperatures
and the same device's registered reference. All data is synthetic. Their shared
device name does not establish a causal link or a reliable real-plant diagnosis.
The lecture and seminar result envelopes differ and are explained explicitly.

Use INSTRUCTOR.md for the mentor's route selection and saved teaching steps. PRESENTATION.md defines readable explanations and genuine choice cards.
TEACHING.md describes the tasks, MCP_GUIDE.md supplies the full MCP teaching
reference, and resources/SETUP.md describes dependencies. lecture_demo contains
completed classroom examples; resources contains the four student TODOs.

Saved student sessions keep their course snapshot, code and results. Start a
new session explicitly to study a revised course; older sessions remain
available. Week 1 and Week 2 storage remains unchanged.

The 28-minute MCP block alternates four pairs of short explanations with four
saved mini-checks, followed by the wrapper exercise and final questions. Formal
learning requires a passed response; after an explained answer, the learner must
explain the idea in their own words before continuing.

Nine original slide PNGs are included for review. They load one page at a time.
Older saved lessons remain unchanged; choose a fresh session to use
the revised slide-first script and intermediate checks.
